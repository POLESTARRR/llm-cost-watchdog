What I built because of that answer

If most of the money is spent reading, the lever that matters is not "ask for shorter answers", it is which model reads your context. That is a routing decision, and it has to be made per request, before the call, from the prompt itself. This is the gateway that makes it.

How you would use it: change one setting, not your code.

It is a small server that sits between your app and whichever AI company you use. Your app sends its requests here instead. This reads each one, decides which model should answer it, passes it along, and hands the reply back, writing down what it cost on the way through.

Your app needs no changes. It already speaks the same message format this server does, the way every website speaks HTTP, so pointing it somewhere else is a setting rather than a rewrite. Requests then go to Anthropic, Google, or a model running on your own machine, whichever tier the request needs. The name after wd- in the key becomes the project name in the ledger, which is how per-project cost gets attributed without your code passing anything extra.

Below is the entire integration. The first two lines are settings you export in your shell, not code you write. The third is a line your app already has, with one word changed.

# 1. tell your app where to send requests (this server, instead of the vendor)
export OPENAI_BASE_URL=http://localhost:8000/v1

# 2. name your project. the bit after wd- is what shows up in the ledger
export OPENAI_API_KEY=wd-my-project

# 3. in your code, ask for a group instead of a specific model.
#    the server then reads the prompt and picks the tier for you.
client.chat.completions.create(model="group:ladder", messages=[...])
